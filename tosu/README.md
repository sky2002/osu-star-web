# osu!mania 4K 星数 · tosu 插件（试用）

把网页版星数工具（树星数 v1 / P1h）做成 [tosu](https://github.com/tosuapp/tosu) 计数器。

> ⚠️ **没在真实 tosu 里测试过。** 作者本机没装 tosu，只在自己写的模拟 tosu（`tools/mock-tosu.mjs`）上测过，直接发出来了，就是这么大胆。
> 能不能用、哪里坏了，欢迎到 [Issues](https://github.com/sky2002/osu-star-web/issues/new) 反馈。

选歌时自动读出当前谱面的星数，同时考虑当前 Mod。读数和网页版是同一套计算，全部在本机进行，不上传谱面。

> **请在选歌界面打开本插件，不要在打歌途中启用。**
> 首次加载模型（约 16 MB）和计算会占用 CPU，可能造成卡顿。
> 插件检测到正在打歌时会自动暂停：不加载模型；正在进行的计算会被中止，回到选歌界面后再重新计算。

## 安装

1. 安装并运行 tosu。
2. 把 `osu-star-tosu` 整个文件夹放进 tosu 的 `static` 文件夹（tosu 设置里叫 counters / static 文件夹）。
3. 打开 `http://127.0.0.1:24050/`，在本地计数器列表里找到“osu!mania 4K 星数（P1h）”。
   可以添加为 OBS 浏览器源，也可以加入 tosu 的游戏内叠加层。建议大小 380 × 220。

### 设置

在 tosu 的设置页面（计数器旁边的设置按钮）可以改：

- **打歌时隐藏插件**：开启后，打歌时整张卡片隐藏，回到选歌或结算界面再显示。默认关闭。打歌时插件本来就不计算，这个开关只管显不显示。
- **卡片底部显示**：三选一，默认“使用提示”。
  - 使用提示：卡片底部的“请在选歌界面打开，不要在打歌途中启用”。
  - 难度曲线：和网页版一样的分段难度曲线，每 10 秒一段，高亮最难的一段；打歌时用竖线标出当前位置。曲线用旧的公共星数刻度，只看起伏，不等于总星数。
  - 不显示：只留星数和段位。
- **显示我的水平与预计 acc**：默认开启，见下面“我的水平与预计 acc”。
- **用最近几局估水平**：默认 5 局（1–20）。
- **辅助线程数**：长谱计算时额外使用的线程（0–8，默认 0）。越多越快，但占用更多 CPU；下一次加载模型时生效。

设置需要 tosu 2.6 及以上；更早的版本没有设置页面，插件按默认值运行，也可以在网址后面加 `?hint=0`（底部不显示）、`?curve=1`（底部显示难度曲线）或 `?helpers=2`（辅助线程）。

## 读数说明

- 只支持 osu!mania 4K（不支持转谱）。物件少于 20 个时不计算。
- 星数下面显示 **米段位 / 面段位**（和网页版相同）：米段位用总星数和 REFORM 1st–Eta 段位谱比，面段位用整谱 97% ScoreV2 读数和 LN Dan Courses v2 5th–15th 比，例如“Alpha mid（11.00）”（段内方位词按与最近档位锚点的偏差划分，括号内保留两位小数）。只比较模型读数，不代表能通过对应段位；长条很少的谱面段位变灰；开了 Mod 时用这组 Mod 下的读数和 NoMod 段位谱比。
- 同一张谱、同一组 Mod 只算一次，结果会缓存在浏览器里，重开 tosu 后仍然有效。
- 星数是社区试用读数，不是 osu! 官方星数；口径与已知限制见[网页版说明](https://github.com/sky2002/osu-star-web#readme)。

### 我的水平与预计 acc

tosu 自己不保存游玩记录，插件会自己记：每次从打歌直接进入结算界面（打完，或开 NF 打完），就记下这张谱、Mod 和 acc（按 stable ScoreV1 从判定数算，和 stable 游戏里显示的 acc 一致；lazer 显示的 acc 口径不同）。
不记失败、中途退出、别人的回放（结算界面的玩家名和当前登录的不一致时不记）；只记插件开着时打的局，记录存在插件自己的浏览器存储里，OBS 浏览器源和游戏内叠加层各记各的。

- 每一局用网页版“达成水平”表反推：在这张谱上打出这个 acc，大致相当于多少星的水平（和总星数同一刻度）。acc 低于 85% 或不低于 99% 的局反推不可靠，不计入；星数读数不可靠的局也不计入。
- **我的水平** = 最近 5 局可用成绩反推水平的平均（局数可在设置里改）。
- **预计 acc**：把“达成水平”表正着读，在当前谱面（含当前 Mod）上这个水平平均能打多少 acc，并给出“十局约八局”会落在的区间，例如“预计 acc 95.1%（十局约八局在 92.4% ～ 97.0%）”。
- 结算界面会多一行“这局 ≈ 多少星水平”。

**回测**：用 72 名玩家约 8.9 万局打完的 NoMod 排名谱成绩，按时间顺序用前 5 局预测下一局：十局里约八局落在预计值 −1.9 到 +2.1 个百分点之间（中位误差 0.8 个百分点），比直接用最近 5 局的平均 acc 好（−3.0 到 +2.8）。
误差主要是每一局自己的发挥起伏，用更多局也压不下去。卡片上的区间就是按回测的水平误差（−0.62 ～ +0.64 星）换算的，谱面与水平相差 1 星以内时实测覆盖约八成。

卡片会在这些情况下提示：

- 谱面比你最近的水平难 1 星以上：**不给数字**。回测里这种谱打完的局多半比公式高很多（中位高 4–9 个百分点）。
- 最近几局起伏很大（最高与最低差 2.5 星以上）：区间可能偏窄。
- 水平 3 星以下：实测区间更宽（约 −3 / +9 个百分点）。
- 开了 Mod：区间未经检验（回测只有 NoMod）。

回测只覆盖 NoMod、排名谱、打完的局；DT/HT、非排名谱和失败的局没有测过。

### Mod

| Mod | 处理方式 | 检验情况 |
|---|---|---|
| NoMod | 按谱面原样计算 | 已检验 |
| DT / NC（1.5 倍） | 与网页版 DT 相同 | 已检验（顶端主要是外推） |
| HT / DC（0.75 倍） | 与网页版 HT 相同 | 未经检验 |
| lazer 自定义倍速（0.5–2 倍） | 时间除以倍速，判定区间按 stable DT/HT 的规则随倍速缩放 | 未经检验 |
| HR / EZ | 按 stable 规则，判定区间 ÷1.4 / ×1.4 | 未经检验 |
| Difficulty Adjust 改 OD（lazer） | 用改后的 OD 判定，OD 特征也换成改后的值 | 未经检验 |
| HD、FI、FL、NF、SD、PF、MR 等 | 不影响读数，忽略并列出 | — |
| RD、IN、HO、NR、DS、改键数、WU/WD/AS | 会改谱面或倍速随时间变化，不计算 | — |

树模型只在 NoMod 和 1.5 倍的人群成绩上训练、检验过，其他组合都是同一套规则推出来的，会在卡片上标注“未经检验”。
所有倍速、HR/EZ 和改 OD 的 JS 读数都已与 Python 参照实现逐位核对（`tests/compare_mods.mjs`）。

## 开发

```
node tools/build-tosu.mjs     # 生成 dist/osu-star-tosu/ 和 dist/osu-star-tosu.zip
node tools/mock-tosu.mjs      # 模拟 tosu：http://127.0.0.1:24050/osu-star-tosu/
```

用 `GET /mock?file=<.osu 路径>&state=<5 选歌 / 2 打歌>&mods=<JSON>` 切换模拟状态。
插件代码在 `tosu/`，计算部分直接复制 `docs/js`、`docs/model` 和 `docs/vendor/ort`，不另做修改。
